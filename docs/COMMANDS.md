# Commands

One text command language, used in three places: the `--exec` flag, the
command palette (Ctrl+P), and the console line at the bottom of the Log
tab. `help` lists everything; `help select` explains one command.

```bash
# A publication figure without touching the mouse:
vizviz --exec "load 4HHB.cif; color chain; style white; background #FFFFFF; screenshot fig.png; quit"
```

Commands are separated by `;` or newlines; `#` starts a comment. A
command's tail is taken whole, so paths with spaces need no quotes.

## Document commands

These change the scene, go through undo history, and also work in Python
via `Session.exec()`.

A PSF/PRMTOP's own bond list is used as-is. If TOPOLOGY is already open, the trajectory is attached to that structure instead (`attachtrajectory`). Neither path may contain spaces. File ▸ Add trajectory uses it when "Current structure" is chosen |
| `fetch ID [bcif \| assembly N]` | download an entry from RCSB into the per-user cache (`%LOCALAPPDATA%\vizviz\cache`, `~/.cache/vizviz`) and load it: the asymmetric unit (as BinaryCIF with `bcif`), or biological assembly N. In the app, `fetch` alone opens a dialog |

In the app, a Structures panel row's own eye |

| `selectmode shape click\|box\|circle\|lasso\|toggle\|next`, `selectmode level atom\|residue\|chain\|molecule\|next` | the Home ▸ Select tool (app only); `shape toggle` switches between `click` and the last shape used, `shape next` (the Q key) cycles the shapes, `level next` cycles the pick level. With a shape other than `click`, a left drag in the viewport draws that shape and, on release, selects the atoms inside it that a visible rep draws (occlusion is ignored: atoms behind others count). Shift adds to the selection, Ctrl or Alt subtracts; middle drag still rolls, right drag pans, and a plain click still picks. `level` grows the hits to their whole residues, chains or molecules (connected atoms). It goes through the same undoable `Select` as a click; `mode`, or Escape in the viewport, returns to `click` |
| `clear` | clear the selection. In the app, Escape in the viewport |
| `saveset NAME`, `useset NAME`, `deleteset NAME`, `sets` | named selection sets (command line only) |
| `representation spacefill\|ballstick\|sticks\|lines\|sas\|tube\|cartoon\|gaussiansurface\|skinsurface\|ses\|glycan [ID]` | the current rep's style; `rep` for short; `sticks` (alias: `licorice`) is thin bonds with balls of the same 0.3 A radius, `lines` bonds as 1-px lines, `sas` atoms grown by the 1.4 A water probe (the solvent-accessible surface as spheres); `tube` is a backbone tube with ligand sticks and no water; `cartoon` is DSSP-shaped ribbons/arrows (no ligands/water yet); `gaussiansurface` (aliases: `gaussian_surface`, `surface`, `gaussian`, `blob`, `blobby`) is a ray-marched blobby molecular surface; `skinsurface` (aliases: `skin_surface`, `skin`) is a ray-cast skin surface (Edelsbrunner 1999), the full mixed complex (sphere, hyperboloid, and void patches for every vertex/edge/triangle/tetrahedron) and pickable; `ses` (aliases: `molecular`, `connolly`) is the analytic solvent-excluded surface for a 1.4 A probe, pickable, of the rep's atoms without water; the clip plane caps it with each cut atom's own disc (see `clip`), and parts smaller than 2 px on screen draw simplified. It is built in the background (about 10 s at 4M atoms) and needs about 300 bytes of GPU memory per atom (in buffers of at most 64 MB); if the GPU runs out it says so and draws nothing. Cartoon and the surfaces re-assign/rebuild every frame during trajectory playback; `glycan` (aliases: `snfg`, `3d-snfg`, `carbohydrate`) draws every glycan residue the rep's selection includes (default: the whole structure) as its 3D-SNFG symbol — the shape, color and size that the 3D-SNFG symbol set (Thieker, Hadden, Schulten & Woods 2016, Glycobiology 26:786) assigns each recognized monosaccharide name (PDB CCD, CHARMM or GLYCAM), oriented by its ring and glycosidic linkage, with gray linkage cylinders to the next sugar or to the glycoprotein's alpha carbon; other residues never draw under this rep, so it is meant alongside another rep for the protein itself. In the app, Represent ▸ Style or a selection row's own compact Style select (both edit the current rep and stay in sync) |
| `color element\|class\|chain\|segname\|fragment\|structure\|restype\|resname\|clustal\|zappo\|taylor\|helix\|strand\|turn\|buried\|nucleotide\|purinepyrimidine\|rainbow\|hetero\|bfactor\|occupancy\|hydrophobicity\|ww\|NAME\|#RRGGBB\|values CHANNEL [ID]` | the current rep's colouring. `class`: one fixed colour per molecule class (protein, nucleic, lipid, glycan, water, ion, small molecule, other; see [SELECTION.md](SELECTION.md)); `structure`: secondary structure (helix purple, 3-10 blue, strand yellow, turn cyan, coil white); `restype`: acidic red, basic blue, polar green, nonpolar white; `resname`: one hue per residue name; `segname`: one hue per segment id (PDB columns 73-76), or per `auth_asym_id` when the structure has none; `fragment`: one hue per connected component of the bond graph; `rainbow`: blue N- to red C-terminus per chain; `hetero`: carbons by chain, other atoms by element; `hydrophobicity` (alias `kd`): Kyte-Doolittle, teal (hydrophilic) to goldenrod (hydrophobic); `ww`: Wimley-White (1996) whole-residue octanol scale, same ramp; `clustal`, `zappo`, `taylor`: the Clustal, Zappo and Taylor residue-type palettes (`clustal` is the per-residue-type reduction of the Clustal alignment scheme, independent of any alignment); `helix`, `strand`, `turn`, `buried`: Chou-Fasman propensity/burial scales, each on its own colour ramp; `nucleotide`: A/C/G/T/U identity; `purinepyrimidine`: purine vs pyrimidine; `occupancy` and `bfactor` on the shared ramp; NAME is a colour name (red, blue, orange, cyan, purple, ...) or `#RRGGBB`; `values CHANNEL`: an attached per-atom channel (element until it is attached). In the app, Represent ▸ Coloring or a selection row's own compact Coloring select; disabled on a glycan rep (its colours are fixed by the 3D-SNFG symbol) |
| `material NAME [ID]` | what a structure is made of: opaque, flat (no shading: ambient 1/diffuse 0/specular 0, so the shading term is exactly the base colour, unaffected by the key/fill lights or the lighting's own ambient term; the viewport's tonemap/ao/shadows/depthcue still apply on top, as for any material -- turn them off for the literal colour), transparent, brushedmetal, diffuse, faint, clearglass/tintedglass/frostedglass, glossy, hardplastic, softmetal, steel, translucent, inked, inkedgloss, inkedglass, textbook, polished, chalk, chalkedge, bubbledglass, hollowglass, mirrorchrome (drawn as opaque; its mirror is ray-tracing only), plus toon, clay (a soft, shadow-free studio look), rim (a bright edge glow, the opposite of an outline's darkened one), studiomatte and labdefault (a matte studio look and a flat lab-default look). Earlier material names still parse as hidden aliases; `material NAME` and saved sessions always write the current name. Materials with opacity below 1 (transparent, clearglass/tintedglass/frostedglass, faint, translucent, inkedglass, bubbledglass, hollowglass) draw as order-independent weighted-blended glass on every representation -- spheres/impostors, bonds and sticks, cartoon, tube, glycan meshes, and the Gaussian/skin/SES surfaces; a click picks the nearest opaque thing, or the nearest transparent one if nothing opaque is behind it. Gaussian/skin/SES surfaces are still one glass layer each (a second overlapping transparent surface resolves to the nearer one; docs/RENDERING.md). Undoable, saved in sessions. In the app, Represent ▸ Material or a selection row's own compact Material select |
| `addrep STYLE [SELECTION]` | draw part of the current structure another way: a new rep with STYLE for the atoms SELECTION picks (default all), coloured and made like the current rep; it becomes current. e.g. `addrep ballstick hetero and not water`. In the app, Represent ▸ Add rep opens this as a form (style, "Draws"); the Structures panel's own expression field (Enter or +) adds one with the current row's style/coloring/material; a selection row's ⋯ ▸ Duplicate copies that row instead |
| `delrep [N]` | delete rep N (default current); the last rep stays (hide it with `showrep`). In the app, a selection row's ⋯ ▸ Delete |
| `selrep SELECTION` | which atoms the current rep draws. In the app, a selection row's own expression (click to edit inline; Enter applies, Escape reverts) |
| `currep N` | the rep that `representation`, `color`, `material` and `selrep` edit. In the app, clicking a selection row (or its ⋯ ▸ Options) |
| `showrep N on\|off` | show or hide rep N. In the app, a selection row's own eye |
| `reps` | list the current structure's reps (`*` marks the current one); the Structures panel's selection rows are its clickable form in the app |
| `values [NAME PATH \| remove NAME] [ID]` | attach a column under NAME from a `.npy` (any numeric dtype; one value per atom or per residue, or `(frames, n)` of either) or a text file (one number per line), list the attached channels with their ranges, or remove one. `savesession` persists an attached channel as a `.npy` sidecar |
| `label ATOM TEXT`, `unlabel ATOM`, `labels` | a text label anchored to an atom of the current structure, billboarded in the viewport and following its current frame position; `labels` lists every label across all loaded structures. Saved in sessions. In the app, Analyze ▸ Label enters a click-atoms mode (Escape or another mode exits) that labels each atom clicked with its own compact tag; the Inspector's Annotations list shows every label (its own "x" removes one), and right-clicking a label in the viewport removes it too |
| `caption NAME X Y TEXT`, `uncaption NAME`, `captions` | a free-floating text caption at fractional viewport position X Y (0..1 from the top-left), not tied to any structure; `captions` lists them. Saved in sessions. In the app, Analyze ▸ Caption opens this as a form; the Inspector's Annotations list shows every caption |
| `frame N [ID]` | show coordinate set N (0-based) of a structure (default: the current structure if it has more than one frame, else the first loaded structure that does). Undoable; this is the frame a saved session persists. Playing back or scrubbing the Timeline tab does not go through this — it would flood undo history — so it doesn't move in lockstep with the slider; use it for a deliberate, one-shot jump from a script or the console |
| `undo`, `redo` | scene edits and view settings/camera jumps (lights, saved views, background, effects, clip, look/light presets, `view reset`, `view face`, a view-cube click, clicking a saved view) share one history; ordinary drag/pan/zoom/wheel are never in it |
| `measure [A B [C [D]]]` | distance, angle, or dihedral (IUPAC sign) between atom indices of the current structure, at its current frame; no atoms: the selection's (2 to 4, in index order). It stays on screen as a dashed line with its value, measured again as the frame changes (so it follows a playing trajectory), is exported with screenshots and SVG, and is saved in sessions. In the app, Analyze ▸ Measure pins the current selection's measurement |
| `unmeasure A B [C [D]] \| all`, `measurements` | take measurements off the screen; list them with their current values. In the app, the Inspector's Annotations list (each row's own "x") |
| `contacts CUTOFF EXPR_A \| EXPR_B` | atom pairs within CUTOFF Å between two selections, and the residue pairs behind them ([ANALYSIS.md](ANALYSIS.md)). In the app, Analyze ▸ Contacts opens this as a form; the result is a card in the Inspector, with Copy |
| `sasa [FILTER] [\| SELECT]` | per-atom solvent-accessible area as [FastSASA](https://github.com/aminkvh/FastSASA) computes it (Shrake-Rupley, 100 points, 1.4 Å probe, ProtOr radii). FILTER is what takes part (default `not hydrogen and not hetero`; `sasa all` includes hydrogens and HETATM); SELECT reports a subset in that context. Attached as the value channel `sasa`. In the app, Analyze ▸ Surface area; the result is a card in the Inspector, with Copy |
| `savestructure PATH [SELECTION] [frame N\|allframes]` | write the current structure to PATH: format from its extension — `.pdb`/`.ent` (wwPDB v3.3 fixed columns; `TER` after each polymer chain; `CONECT` for explicit bonds; `CRYST1` when the cell is known; serials and residue numbers past 5/4 digits use hybrid-36; a chain id longer than one character is remapped to a free letter, falling back to a shared `?` past 62 chains), `.cif`/`.mmcif`/`.pdbx` (no column limits; bonds as `_struct_conn`), `.xyz`, `.pqr` (formal charge and van der Waals radius, not a force field's), `.gro` (nm, a bounding-box-derived box line) — any of them optionally `.gz`. SELECTION restricts which atoms (docs/SELECTION.md; default all, PATH may not contain spaces); `frame N` writes one coordinate set (default the current frame), `allframes` writes every one (`MODEL`/`ENDMDL` or `pdbx_PDB_model_num` per frame). Prints a warning per thing the format couldn't represent exactly. In the app, File ▸ Export ▸ Structure… (also a structure row's ⋯ ▸ Export structure…) opens this as a form: format (by extension, or forced), atoms (all or the current selection), frames (current or all), then the platform's own save dialog; warnings show in a toast |
| `savesession [PATH.vviz]`, `loadsession [PATH.vviz]` | session files: structure and trajectory paths, representations, colorings, frames, value channels (as `.npy` sidecars next to the session file), selection sets (as expressions), the active selection, atom labels, captions, measurements, and in the app the camera, style, up to 4 lights plus ambient, saved camera views, background, effects, playback and the dock layout; loading replaces what is open, step by step through undo history. No path opens a dialog in the app. `.vviz` is plain JSON; a session saved as `.json` before this still opens |

## View commands

These change how the scene looks and exist only in the app (a headless
Python session has no viewport). Lights, background, effects, clip and
look/light presets are undoable, in the same history as scene edits
(B6); `view reset`/`view face` and a view-cube click are too, but
ordinary drag/pan/zoom/wheel camera movement never is -- see `undo`.

| Command | Does |
|---|---|
| `open [PATH]` | load and frame a file; no path opens the "Open a structure" dialog (a typed Path field, or Browse for the platform's own picker) |
| `welcome [on\|off]` | show the viewport's start card now (Open, Fetch, Open session, recent files), closed for the rest of the run once dismissed; `on`/`off` set whether it offers itself automatically over an empty viewport (default: on, unless a file was named on the command line) |
| `preferences` | open Preferences: theme, start behavior, performance, and resetting them |
| `look lights\|background\|ao\|shadows\|depthcue\|dof` | open Look ▸ Lights or Background (also on the Studio tab: up to 4 lights, each with a color, intensity, azimuth and elevation, plus ambient); the effects open Preferences ▸ Effects |
| `style dark\|white\|glossy\|flat` | a look: sets the lights. Effects (Preferences ▸ Effects), materials (`material`) and the background (`background`) are each their own choice, left as they are |
| `lighting default\|soft\|full\|flat\|illustrative\|gentle\|twinlight\|threepoint` | global lighting (effects stay as they are). `default` is a bright two-light rig with a small ambient term; `twinlight` is two full-intensity lights with no ambient and no depth cue; `soft`, `full`, `flat` and `gentle` are further presets from even to high-contrast; `threepoint` (alias: `studio`) approximates a bright three-point look |
| `tonemap [on\|off]` | ACES tonemapping of bright highlights |
| `background R G B` / `#RRGGBB` / `default` | viewport background |
| `gradient R G B \| #RRGGBB \| on \| off` | fade the background to this colour at the top; `on` picks a lighter shade, `off` is solid |
| `shadows on\|off\|STRENGTH` | screen-space shadows from the key light (0-1); on by default with `lighting full` |
| `dof on\|off\|STRENGTH` | depth of field (0-1): sharp at the rotation centre, blurring with depth distance from it |
| `framing [on\|off]` | overlay a safe-frame rectangle on the viewport at File ▸ Export ▸ Render's own width:height, dimming outside it; also shows while that popover is open. In the app, Studio ▸ Frame preview |
| `theme dark\|light` | the interface's colours; saved with the layout |
| `ribbon TAB\|collapse\|expand` | open a ribbon tab (file, represent, look, analyze, view, studio) or fold the ribbon to its tab names |
| `panel NAME` | show a dock panel: viewport, structures (`scene` still works, its old name), selection, inspector, sequence, log, info, timeline, movie. `settings`/`look` open the Look ribbon tab instead (its panel is gone); `panel` alone opens View ▸ Panels ▾ |
| `play [on|off|FPS]` | play or pause a multi-frame structure; a number plays at that many frames per second (a streamed trajectory steps only onto frames already read, so slow reads slow it down) |
| `deletelayout [NAME]` | forget a saved workspace; alone, lists them to choose from (and asks before deleting) |
| `uishot PATH` | write the whole window as a PNG (for docs and UI review) |
| `startlayout [reset]` | open the current panel arrangement at every launch; `reset` goes back to the built-in default; without a start layout every launch opens the default |
| `repopt [NAME VALUE\|default]` | tune the current rep: spacefill/ball-and-stick atom `scale` (× van der Waals), `bond` radius (ball-and-stick, sticks), tube `radius` (its thick end once `radius_by` is 1), `radius_min` (its thin end) and `radius_by` (`0` constant, `1` by B-factor: linear from `radius_min` to `radius` over the B-factor range of the tube's own atoms), glycan-linkage `radius`, glycan `size` (a shape's overall size; `size` 4 with `radius` 0.5 is the full symbol, `size` 1.5 with `radius` 0 the compact icon), SAS/SES `probe` radius, Gaussian `blob`, skin `shrink`; alone, lists the options with their ranges. Saved in sessions. In the app, the current rep's own Options in the Structures panel (folded under "Advanced" once there are more than a couple) |
| `window WxH` | resize the window to W x H logical pixels (at least 1024 x 640), for checking the layout at a size |
| `clip [on\|off\|view\|x\|y\|z\|flip\|DEPTH]` | cut the scene with a plane through the rotation centre: every solid (spheres, bonds, the cartoon tube, and the Gaussian, skin and solvent-excluded surfaces) shows a flat cap of its own colour where it is cut, and empty space (cavities, the gaps between atoms) stays open. `view` faces the camera and tracks it as you rotate (the default when turned on); `x`, `y`, `z` fix it to that world axis instead; `flip` keeps the other side. DEPTH (Å) moves the plane along its normal, away from what it keeps. The skin and solvent-excluded surfaces cap with each cut atom's own van der Waals disc, not their own patches (a patch never covers a buried atom); `render` caps spheres the same way but leaves bonds, the cartoon and the surfaces cut open for now. In the app, `clip` alone opens View ▸ Clip's ▾ |
| `rotate [x\|y\|z DEGREES]` | turn the scene about a screen axis. In the app, `rotate` alone opens View ▸ Rotate's form (dragging in the viewport is a trackball, not this command) |
| `supersample 1\|1.5\|2` | render the viewport larger and average down; sharper thin geometry at 4x the pixels for 2x |
| `fxaa`, `outline`, `occlusion`, `adaptive` `[on\|off]` | quality toggles; no argument flips. Outline is dark lines on silhouettes and creases (Flat/Cel turns it on) |
| `ao [on\|off\|STRENGTH]` | ambient occlusion: darkens grooves and pockets (0–2, on = 1; off by default) |
| `depthcue [on\|off\|STRENGTH]` | depth cue: fades toward the background with distance from the scene's front, most visible near its silhouette (0-1, on = 0.5) |
| `view reset` / `view orbit YAW PITCH` / `view zoom F` / `view dolly D` / `view face +X\|-X\|+Y\|-Y\|+Z\|-Z` / `view projection perspective\|orthographic` | camera; degrees, `F > 1` moves away; `dolly` moves the camera itself D Å forward (negative: back; Shift+wheel in the viewport), cutting the scene flat and capped where it passes (orthographic: from the front of the framed scene), and `reset` undoes it; orthographic drops distance-based size falloff; `face` looks from that side, as clicking the view cube (top right of the viewport; a scale bar sits bottom left). Studio ▸ Views ▾ (no console verb) bookmarks the camera under a name and flies back to one on click, saved in sessions |
| `layout [NAME]` | switch workspace (`default`, `trajectory`, `analysis`, `compact`, or a saved one); alone, opens View ▸ Layout ▾ |
| `savelayout [NAME]` | save the current panel arrangement as a workspace |
| `screenshot [PATH] [nossaa]` | write a PNG, a JPEG if PATH ends in `.jpg`/`.jpeg` (2x supersampled unless `nossaa`), or a vector SVG if PATH ends in `.svg` (atoms only, as depth-sorted circles; no bonds/cartoon yet, `nossaa` has no effect); no path opens the dialog |
| `render [PATH] [WxH] [SAMPLES] [draft\|high\|ultra] [transparent]` | path-trace the view into a PNG/JPEG: real shadows from every enabled light and ambient occlusion, in the viewport's lighting and materials, antialiased; any size (default the viewport's), SAMPLES per pixel (default by quality). Quality (default `high`) sets the sample count and the cartoon/tube tessellation (denser than the viewport's) together; `draft` is fast and coarse, `ultra` the slowest and smoothest. PATH may be quoted (`"C:/My figures/a.png"`). `transparent` for no background. Runs in the background with progress in the viewport's lower-right corner (an `--exec` script waits for it). Draws every representation: the SES and skin surface exactly as the viewport casts them (rebuilt first, which takes seconds on large structures), the Gaussian surface as a fine mesh of the same field. A failed render stops an `--exec` script. In the app, `render` alone opens File ▸ Export ▸ Render's form, with a Quality selector; while that popover is open (or with Studio ▸ Frame preview / `framing on`), a safe-frame rectangle at the render's aspect ratio overlays the viewport |
| `movie ...` | the movie maker (see [Movies](MOVIE.md)): `movie` opens the panel; `movie addtrack rotate\|zoom\|moveto\|play`; `movie clip TRACK START LENGTH ARGS [linear\|ease]`; `movie removetrack N`; `movie removeclip TRACK CLIP`; `movie set fps\|duration\|size VALUE`; `movie time SECONDS`; `movie play [on\|off]`; `movie list`; `movie clear`; `movie export DIR [nossaa] [nomp4] [nopng] [gif] [nodither] [gifwidth=N]` (numbered PNGs, plus movie.mp4 if ffmpeg is on the PATH; `gif` also writes movie.gif, 256 colours per frame, dithered unless `nodither`, at most 800 px wide unless `gifwidth=N`; `nopng` skips the PNGs and the MP4 built from them; a script waits for it) |
| `confirmquit [on\|off]` | ask to save before quitting when there are unsaved changes (default: on); `off` is what the quit dialog's "Don't remind me again" checkbox sets |
| `quit` | exit, saving the layout |

On Windows, `vizviz` is a windowed program that borrows the shell's console
when started from one, so `--exec` output appears in your terminal. `cmd.exe`
and PowerShell do not wait for windowed programs: for scripted runs there
use `start /wait vizviz --exec "..."` (cmd) or pipe the call, e.g.
`vizviz --exec "..." | Out-Host` (PowerShell). Bash-style shells wait.

## How `--exec` runs

Commands are validated before the window opens (an unknown verb, or a
command that would open a dialog because its path is missing, exits with
code 2) and then run one per frame, starting once the viewport has
settled at its docked size. That is why `load ...; screenshot ...` works:
the load is uploaded and drawn before the screenshot is taken. Each
command and its result are echoed to the terminal and the Log tab.

The first command that fails at run time (a missing file, a bad style
name) stops the script, closes the window, and exits with code 1, so a
shell script or CI job can tell. `Session.exec()` behaves the same way:
it stops at the first failure and raises `ValueError` naming it.

`version` prints the command language's version (docs/VERSIONING.md).
A running window started with `--listen` takes the same scripts from
other programs, Python and MCP clients: see [LIVE.md](LIVE.md).

## For agents

`vizviz --exec help` and `vizviz.Session.commands()` are the machine-
readable lists. Every command is one line of text with a fixed verb, so
an agent that can call a shell or Python can drive the whole app.
